# 順番4：手法を作る期間の区画の、欠けた日の一覧（T-087）

この文書は、手法を作る期間の区画（2015-03-02〜2020-12-14）について、欠けた日の一覧をどう作るかを定める。
一覧を作るコードは `src/stats/missing_days.py`、テストは `tests/stats/test_missing_days.py`。
封印は封印係が行う。統計係はこの文書とコードを作るだけで、封印しない。

## 1. 規則

規則は docs/stats/candidates.md 3章 (5)（seq 2 で封印済み）のとおりで、この文書では変えない。要点を引く。

- 日の区切りは、収集係の規則（15分ファイルの時刻と UTC の暦日の対応。src/collector/filelist.py）に従う。
- 「取得できたファイル」は、ファイル一覧に載り、取得の記録で取得とハッシュの照合に成功した15分ファイル。
- 次のどちらかに当たる日を欠けた日とする（`candidates.day_is_missing()`）。
  - 取得できたファイルが96本のうち72本未満
  - 取得できたファイルから数えた全体の報道量が0
- 一部が欠けた日（72本以上96本未満）は欠けた日としない。

コードは、判定に `candidates.day_is_missing(present_slots, total_volume)` をそのまま呼ぶ。72・96 の値も candidates.py の定数（`MIN_PRESENT_SLOTS`・`SLOTS_PER_DAY`）から取る。

## 2. 規則の二つの量を、マニフェストのどの欄で数えるか

| 規則の量 | マニフェストの day の行の欄 |
|---|---|
| 取得できたファイルの数（present_slots） | `files_ok` |
| 取得できたファイルから数えた全体の報道量（total_volume） | `docs` |

**`files_ok`**：収集係の取得のコード（src/collector/gkg.py）が、その日のファイル一覧に載ったファイルのうち、取得とハッシュの照合に成功したものを数えた値である。

**`docs`（全体の報道量の読み方）**：candidates.md 168行の「取得できたファイルから数えた全体の報道量」は、どの数え方かを定めていない（T-085 の報告 4-1）。リードの判断（reviews/T-085.md「2026-10-15 リードの判断」1）に従い、**取得できたファイルの記事（文書）の数**と読む。これはマニフェストの day の行の `docs` と同じ数である。

リードの判断の理由（reviews/T-085.md から引く）：
- 前提1：CLAUDE.md は、報道量を記事の数として扱っている。
- 前提2：C7 の分母（V1・V2 にテーマの付いた記事の数）を「全体の報道量」と読むと、counting.md 259行の「欠けた日でない日に C7 の分母が0なら順番5を止める」が、起こりえない分岐になる。
- 結論：「全体の報道量」は、取得できたファイルの記事（文書）の数とする。

この読み方を取ると、欠けた日の一覧はマニフェストだけから決まり、日の集計を開かずに作れる。
candidates.md と counting.md の文言は変えない。この文書は読み方を足すだけである。

## 3. 入力

- 入口は `src/collector/gkg.py` の `official_day_records()` だけとする。
  - この関数は、最初に封印係の関門 `ledger.require_gkg_run_result("official", run_id)` を呼ぶ。gkg-run-result の記録（seq 12。マニフェストの時刻証明）が無い・合わなければ、マニフェストを読まずに止まる。
  - 読むのは、gkg-run-result が封印したマニフェスト（`data/manifest/gdelt-gkg-method.jsonl`）の先頭だけである。
- **日の集計のファイル（保存先の `.tsv.gz`）は開かない。** マニフェストの day の行の `files_ok`・`files_listed`・`docs` だけを使う。
- 取得の記録（fetch log）も読まない。`files_ok` は、マニフェストを書いた時点で取得の記録から数えた値で、その照合は封印係の検証手順が受け持つ。
- ネットワークは使わない。現在の日時を読まない。ファイルを書かない（標準出力だけ）。

**入力の検査（合わなければ一覧を作らずに止まる）**：
- 区画の各日に、正式な run（mode が official）の day の行がちょうど1つある。行の無い日、区画の外の行、同じ日の二つの行があれば止まる。行の無い日を推測で埋めることはしない。
- run_id が1つだけ。
- `files_ok`・`files_listed`・`docs` が0以上の整数で、`files_ok` ≤ `files_listed`、`files_ok` ≤ 96。
- 区画の端は `periods.FROZEN_BLOCKS` の method の区画と、`gkg.DATA_START`・`gkg.METHOD_BLOCK_END` の両方と一致する。

## 4. 出力の形

コマンド（プロジェクトのルートで）：

```
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B src/stats/missing_days.py            # 一覧の JSON
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B src/stats/missing_days.py --sha256   # その JSON の sha256
```

JSON は UTF-8、キーの順（`sort_keys`）、`indent=2`、末尾に改行1つ。sha256 は、この出力のバイト列全体の値である（`shasum -a 256` と同じ値）。

| キー | 中身 |
|---|---|
| `label` | `missing-days-method-v1`（仮の名前。版の番号は封印の記録の長さで決まる） |
| `block` | 区画の名前と端（`method`、2015-03-02、2020-12-14） |
| `rule` | 規則の出典、使う関数、96・72、二つの量をどの欄で数えたか |
| `input` | 入口、run_id、day の行の数、日の集計を開いていないこと |
| `days_in_block` | 区画の日数 |
| `missing_count` | 欠けた日の数 |
| `missing_days` | 欠けた日の一覧（日付の順）。各日に `day`・`files_ok`・`files_listed`・`docs`・`below_min_files`（72本未満か）・`zero_docs`（docs が0か） |
| `partial_days_count` | 一部が欠けた日（72本以上96本未満）の数。欠けた日には入れない。比率は取得できたファイルだけで数える |

`files_listed` は、欠けの原因がファイル一覧の側（一覧に載ったファイルが少ない）か、取得の側（一覧に載ったが取得できなかった）かを読み分けるために出す。規則の判定には使わない。

## 5. 封印の時機

- **判定（島かどうか）を一つも計算しないうちに封印する。** 手法を作る期間の区画の判定も含む。
- **順番5（タグの一覧の結果。日の集計を開く）より前に封印する。** candidates.md 3章 (5) は「モデルより前（遅くとも threshold-access より前）」とするが、順番5 より前に置けば、この両方より前になる。
- 封印より前に、この区画の取り直しをする場合は、candidates.md 3章 (5) のとおり、取得できなかったファイルのすべてに収集係のコードの同じ手順で行う。**封印のあとは取り直さない。** 取り直した場合は、新しいマニフェストと gkg-run-result の封印のあとで、この一覧を作り直す。
- 封印の kind、記録の中身、照合（出力の sha256、コードと文書の sha256、マニフェストの gkg-run-result の seq との対応）は封印係が決める（reviews/T-085.md のリードの判断 3）。

封印の対象として想定しているもの：
- 上のコマンドの出力（JSON）とその sha256
- この文書
- `src/stats/missing_days.py`（中で使う `src/stats/candidates.py`・`src/stats/periods.py` は封印済みの版と同じもの）
- `tests/stats/test_missing_days.py`

## 6. 順番5 との関係

- 順番5 の記録は、参照に**この順番4 の記録（seq と出力の sha256）**を入れる（reviews/T-085.md のリードの判断 2。4-2）。
- 順番5 では、欠けた日の比率を値なしとして扱う（candidates.md 冒頭の r(d) の定義：欠けた日は値を持たない）。どの日が欠けた日かは、この一覧だけで決め、順番5 の中で数え直さない。
- 参照を記録に入れる仕組みは封印係のタスクで扱う。

## 7. 限界

**2020年秋の欠け**：T-082 の監査は、規則を当てると欠けた日は48日になると見込んだ。2015-05-29、2015-10-21、2015-10-22 と、2020-09-28〜11-17 のうち45日である。2020年秋の欠けは、手法を作る期間の区画の終わり（2020-12-14）に近い。

この欠けの影響について、T-085 の報告は次のように見込んだ。**どれも推測で、データで確かめてはいない。**
- （推測）2020年秋の欠けはエンバーゴの中にあり、期間の区切りは変わらない。
- （推測）手法を作る期間の最後の数回の予言で、判定期間が欠けた日に入る。判定期間の7日のまとまりに欠けた日があればそのまとまりは使わないので、判定不能の予言が増えうる。
- （推測）手法を作る期間の最後の四半期では、存在の条件で外れるテーマが増えうる。
- （推測）閾値を決める期間の最初の約1年の予言では、普段の水準 B(t)（t-371 から t-1）がこの区画の日を読む。欠けた日は使えるまとまりを減らすので、B(t) と、一度跳ねたタグの扱い（冷却）に響きうる。

ほかの限界：
- 欠けた日は日単位で決まり、タグに依らない。一部が欠けた日の比率は、取得できたファイルの時間帯に偏りうる（candidates.md 3章 (5) の72本の理由のとおり、大きさよりばらつきに効くと見込む。これもデータで確かめていない）。
- 72本は、データを見ずに決めた値である（candidates.md）。境目のすぐ下やすぐ上の日があっても、結果を見て値を変えない。
- `files_ok` と `docs` は収集係のコードが数えた値で、この一覧のコードは数え直さない。数え方の正しさは、収集係のテストと封印係の照合に依る。

## 8. 結果を見て変えないこと

- この文書の規則・読み方・入力は、一覧の結果を見る前に決めた形のまま使う。結果（件数や日付）を見て、規則・読み方・72本の値・入力の検査を変えない。
- テスト `TestRealManifestNoAggregates` は、本物のマニフェストで、日の集計を開かないことと出力が毎回同じことだけを確かめる。件数や日付は固定しない。
