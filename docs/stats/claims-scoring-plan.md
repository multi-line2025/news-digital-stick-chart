## 1. 対象と予言日（4段とも同じ）

- 予言日：前向きの予言の予言日（毎週1回）。4段と、入れ子の並びのモデル（2章 (5)）は、同じ予言日のすべてに確率を付ける。
- 対象：予言日 t の各タグの状態を `scoring.target_status()` で決め、"target" のタグだけを対象にする。状態の決め方は naive-scoring.md 4章 (1) のとおりで、変えない（6章）。
- 採点する行：対象の行のうち、判定（candidates.judge）が判定不能でない行。判定不能の行は、どの段でも採点しない（candidates.md 3章 (5)）。
- 4段とモデルは、すべて同じ行で採点する。ある段だけ確率が付かない行は作らない（どの段の確率も、予言日 t の時点で、どの対象の行にも決まるように作る。2章）。
- 対象が0件の週の扱いは naive-scoring.md 4章 (2) のとおり（試行に数えない。記録は残す）。
- 確率は、予言日 t の時点で入手できたデータ（t-1 以前）だけで作る。島の判定の結果は、判定期間が予言日より前に終わった行のものだけを使う（2章 (2)）。

## 2. 各段の作り方

記号：予言日 t、倍率 m、判定期間 H 日、最低の報道量 V（封印済み）。m と H は閾値を決める期間で選ばれた組（8章）。

### (1) 段1（一様の段）
- すべての対象に、同じ確率を付ける。
- 形の候補（T-134 で探索した形）
  - null_exp：予言日 t の時点で判定が確定した行（下の (2) の条件）すべての (島 + 1) / (行 + 2)。
  - null_fix：手法を作る期間の対象の行の島の割合（定数）。
- どちらを段1 にするかは、3章 (6) の規則で手法を作る期間の結果から決める（値は 8章。案）。

### (2) 段2（履歴の段）
- タグ i の確率 = (k_i + a × p0) / (n_i + a)。
  - k_i・n_i：予言日 t の時点で判定が確定した、タグ i の対象の行の島の数と行の数。
  - 判定が確定した行：予言日 s の判定期間 s+1〜s+H が t-1 までに終わった行（s + H ≤ t − 1）。週の番号で数えると、s が t の ceil((H + 1) / 7) 週以上前の行（H = 28 なら5週以上前）。
  - 使う過去の長さ W（全期間、または直近52週）：s が W の中にある行だけを数える。全期間は、前向きの予言では、封印した区画のデータで判定が確定している最も古い予言日からとする（8章の (4) で決める）。
  - p0：段1 の null_exp の値。a：縮めの強さ。
- そのままの形を確率にする（オーナーの決定4）。学習の行で較正し直すことはしない。
- 形（W と a）は、3章 (6) の規則で決める（値は 8章。案）。

### (3) 段3（素朴な予測）

### (4) 段4（スティックチャート）

- 足す列の候補：T-134 で探索した nbwave（網の1歩・2歩の隣の上がり）、chain（連鎖の励起）、その両方。method.md の三つの信号の作り方がこのあと変わった場合は、閾値を決める期間のデータに触れる前に封印した最終の候補の一覧を使う。
- どの形にするかは、3章 (6) の規則で決める（値は 8章。案）。係数は手法を作る期間の対象の行で当てはめ、最初の threshold-access より前に封印する。

### (5) 入れ子の並びのモデル（主張2 の主の示し方のため）
- N3：段3 の特徴量に logit(段2 の確率) を足したロジスティック回帰（リッジ 1）。
- N4：N3 に段4 の足す列を足したロジスティック回帰（リッジ 1）。

## 3. 主張1の判定

主張1（CLAUDE.md）：予言の時点で静かなテーマでも、判定期間のうちに島になる確率には、事前に予測できる差がある。

### (1) 主の判定（段3 対 段1、対数損失の差）
- 行ごとの対数損失：L(p, y) = −log(p)（島）、−log(1 − p)（島でない）。p は 1e-15 と 1 − 1e-15 のあいだに収める（explore_signals.log_loss_terms と同じ）。
- 差：D = 段3 の対数損失 − 段1 の対数損失を、採点する行ごとに求める。
- 主の量：判定の時点までの採点する行すべての D の平均。
- 束：4章 (1) の束。束ごとに、D の和と行の数を求める。
- ブートストラップ：束を復元抽出で選び直し（束の数と同じ回数）、選んだ束の D の和 ÷ 行の数の和を求める。これを B 回くり返す。B と乱数の種は 8章 (6)（案：B = 10000、Python の random.Random、種 137）。
- 95% の範囲：B 個の値を小さい順に並べ、ceil(0.025 × B) 番目と ceil(0.975 × B) 番目（最近順位。explore_signals.bootstrap_diff と同じ取り方）。
- 判定の条件：判定の時点（4章 (2)）で、95% の範囲の上端が 0 より小さい。満たせば「主張1の主の判定を満たした」と書き、満たさなければ「満たさなかった」と書く。どちらも公開する。
- 判定は、主にする倍率と判定期間（8章 (1)(2)）について一度だけ行う。

### (2) 副の判定（Holm の方法）
- 族 S1（主張1 の副）：次の3つの比べを一つの族にする。どれも片側の比べで、同じ束・同じブートストラップ（同じ選び直しの束の並び）で作る。
  1. 段3 対 段2 の対数損失の差（段3 − 段2 < 0 か）。静的な違い（タグの普段の大きさ）を差し引いた比べ（オーナーの決定1 の副）。
  2. 段3 の AUC − 段1 の AUC（> 0 か）。
  3. 段3 の AUC − 段2 の AUC（> 0 か）。
- 片側の p の値：比べの値が「効く」向きでなかった選び直しの割合。p = (1 + 向きでなかった回数) / (B + 1)。
  - 「向きでなかった」：対数損失の差なら 0 以上、AUC の差なら 0 以下。
- Holm の方法：族の中の p を小さい順に p(1) ≤ p(2) ≤ p(3) とし、p(j) ≤ α / (3 − j + 1) を j = 1 から順に確かめ、初めて満たさなかったところで止める。止まる前のものを「Holm で確かめた」とする。α = 0.025（主の判定の 95% の範囲の片側と揃える）。
- AUC は、選び直した束の行をまとめて、順位による AUC（同じ値は平均の順位。explore_signals.auc と同じ）で求める。
- 較正：段3 の ECE（確率の順に件数の等しい10区分。|区分の確率の平均 − 島の割合| の件数の重み付き平均）と、確率の平均 − 島の割合を、同じブートストラップの 95% の範囲付きで示す。較正は族 S1 に入れず、記述として示す（検定にしない。差が無いことを示す比べには、許す幅を前に決める必要があり、その幅をデータを見ずに決める根拠が無いため）。

### (3) 示す形
- 主の判定の結果と並べて、各段の対数損失・ブライア・AUC・ECE・上位10の島（週ごと、同じ確率なら名前の順）を示す。段1 の上位10の島は名前の順で決まるので、段1 を基準にした上位10の差は示さない。
- 主にしない倍率（二段のうち主でない方、8章 (1)）の結果も、同じ計算で並べて示す。主の判定と族 S1 には入れない。

## 4. 束ねた評価と、判定の時点

### (1) 束
- 前向きの最初の予言日から、連続する b = ceil(H / 7) 週の予言日を一つの束にする（H = 28 なら4週）。束は重ならない。
- 理由（前提 → 結論）
  - 前提：予言日 s と s + 7k の判定期間は、k < H / 7 のとき重なる（naive-scoring.md 4章 (1)）。一つの出来事は、その前の最大 ceil(H / 7) 週の予言をそろって島にしうる。同じ週の中の関連するタグは、同じ出来事で一緒に跳ねる。
  - 結論：週の中の行と、判定期間が重なる隣の週を同じ束に入れれば、束の中の依存は束の外に出にくい。束の境目をまたぐ重なりは残る（下の感度で示す）。
- 出来事のまとまり：同じ週に跳ねたタグは同じ束に入るので、週の中の出来事のまとまりは束で扱われる。週をまたぐ出来事のうち束の境目をまたぐものは、(3) の感度（束を2倍にしたもの）で示す。判定のあとに人が出来事をまとめることはしない。
- 採らなかった案：naive-scoring.md 4章 (4) の「同じ週に跳ねたタグを、予言の時点で分かる情報（共起の網など）でつないでまとめる」案は採らない。
  - 前提：その案がまとめるのは、同じ週の中のタグどうしである。束は週をまるごと含むので、同じ週のタグはすべて同じ束に入る。
  - 結論：網でつないでまとめても、束の中の分け方が変わるだけで、束を単位にしたブートストラップの値は変わらない。束をまたぐ出来事は、網でつないでも束の境目では分けられないので、(3) の感度（束を2倍にしたもの）で示す。
- 対象が0件の週も束の週に数える（行が0の週として）。束の行が0件なら、その束はブートストラップから除き、除いた数を公開する（naive-scoring.md 4章 (2)）。

### (2) 束の数の下限と判定の時点
- 判定が出そろった束の数え方
  - 束の暦：束は前向きの最初の予言日から、暦の上で b 週ずつ区切る。途中の週が欠けても、区切りはずらさない。
  - 束の中のすべての予言日について、判定期間が終わり、判定に使うデータがそろったとき、その束を「判定が出そろった束」とする。
  - 採点する行が1件以上ある束だけを、束の数（下限と N_J）に数える。行が0件の束は数えず、その数を公開する（4章 (1)）。
  - 予言の失敗の週：決まった時刻に予言を出せず、確率が封印されなかった週は、どの段の行も無い週として扱う。あとから確率を付け直して足すことはしない。4段・N3・N4 の一部の段だけ確率が無い週は、同じ行を使う決まり（1章）により、その週のすべての段の行を採点から除く。どちらの週も、数と理由を公開する。
  - 束ごとに、束の週の数、予言が出た週の数、予言の失敗の週の数を公開する。
  - 予言が出た週が束の週の半分未満の束を、N_J の数に数えるか（案。8章 (12) でオーナーの確認に回す。どちらの形も並べる）
    - 形1：数える。採点する行が1件以上あれば、ほかの束と同じく数える。束の数え方が単純で、数えるかどうかを選ぶ余地が無い。予言の少ない束が、ほかの束と同じ重みの単位として選び直される。
    - 形2：数えない。その束の行は採点とブートストラップに入れるが、N_J の数には入れない。予言の少ない束で判定の時点が早まることは無いが、判定の時点が遅れる。
    - どちらの形でも、決まりは最初の threshold-access より前に封印し、前向きの予言の結果を見てから変えない。
- 束の数の下限：10（案。8章 (7)）。下限を下回る束の数でのブートストラップの範囲は狭く出がちで、判定に使わない（T-134 の探索で、13・26週の窓（束 4・7）を判定に使えない目安とした。claims-scoring-plan-draft.md 5章）。
- 判定の時点：前向きの予言の、判定が出そろった束の数が N_J に達した時点で、一度だけ主の判定と族 S1 の判定を行う。N_J は 13（案。8章 (7)）。H = 28 なら 52 週の予言日に当たる。
- 判定の時点の前：毎週、そこまでの値（主の量・95% の範囲・族 S1 の値）を公開してよいが、「途中の値（判定に使わない）」と明記する。途中の値が条件を満たしても満たさなくても、判定の時点を早めたり遅らせたりしない。
- 判定の時点のあと：同じ計算を続けて公開する（「判定の時点のあとの値」と明記する）。主張1 の判定は、判定の時点の一回の結果とする。
- 前向きの予言が途切れたとき：予言が止まった週も束の暦は進め、再開したあとも同じ暦で束を数え続ける。判定が出そろった束の数が N_J に達した時点で判定する。前向きの予言を終えるまでに N_J に達しなかった場合は、「判定できなかった」と書き、そこまでの値は「途中の値（判定に使わない）」のまま残す。少ない束の数で判定し直すことはしない。
- 前向きの予言を続ける長さ：少なくとも、判定が出そろった束の数が N_J に達するまで続ける。続けられない理由（データ源の停止、利用条件の変更など）が出たときは、その理由と、その時点の束の数を公開する。

### (3) 感度（判定に使わない。記述として示す）
- 束を2倍の長さ（2b 週）にしたブートストラップの範囲。
- 束を一つずつ抜いたときの主の量の変化（影響の大きい束）。
- 島の割合が多い週（判定の時点までの週ごとの島の割合の上位10%）を除いた主の量。

## 5. 主張2の示し方

主張2（CLAUDE.md）：その予測可能性のうち、どこまでがテーマ自身の過去の動きで説明でき、どこから先を情報の網の構造が説明するかを分ける。

### (1) 主：入れ子の並び（2-b）
- 上乗せ：2−1（段2 − 段1）、N3−2（N3 − 段2）、N4−N3（N4 − N3）。
- 各上乗せを、対数損失の差の平均と、3章 (1) と同じ束・同じブートストラップの 95% の範囲で示す。勝ち負け（範囲が0を含むか）でなく、大きさとその幅を主に示す。
- 上乗せは順に引いた差なので、三つの和は N4 − 段1 に等しい。入れ子の並びでは、後の段のモデルが前の段の確率（または特徴量）を入力に持つ。

### (2) 並べるもの：段の並びのまま（2-a）
- 上乗せ：2−1、3−2、4−3。同じ形で示す。
- 段2 と段3 は入れ子でないので、3−2 には「段2 の持つ情報を段3 が別の形で持つ分」が入る。2-a の 3−2 と 2-b の N3−2 を並べて示す。

### (3) 識別と較正（2-d）
- 各段とモデルの AUC と ECE を、3章 (2) と同じ取り方で、95% の範囲付きで示す。
- 較正し直した対数損失（識別の目安）：採点する行の上で、確率を [1, logit(p)] にロジスティック回帰し直した対数損失の平均。上乗せごとに、較正し直した対数損失の差と、較正の損（対数損失 − 較正し直した対数損失）の差を示す。
  - 採点する行で当てはめるので、前向きの予言には使えない事後の記述である。
  - 較正し直しのリッジ：0（リッジを掛けない）とする案（8章 (5)）。T-134 の探索ではリッジ 1（切片を含む）を掛け、確率の幅が狭い形で大きく歪んだ（explore-t134r2 の要約1章）。
  - 確率が一定、またはほぼ一定の形（段1 など）：リッジ 0 では、切片の列と logit(p) の列がほぼ同じ向きになり、ニュートン法の行列が特異（またはほぼ特異）になって計算が止まる（監査係が naive._solve で確かめた。段1 の null_exp もほぼ特異）。扱い方の案を3つ並べる（どれも案。8章 (5) でオーナーの確認に回す）。
    - 案A（統計係の案）：切片だけで較正し直す。採点する行の logit(p) の標準偏差が S_MIN 未満の形では、[1] だけのロジスティック回帰（確率 = 採点する行の島の割合）の対数損失を、較正し直した対数損失とする。S_MIN = 0.05（案。データから導いた値ではない）。標準偏差は、採点する行すべての logit(p) の母標準偏差（n で割る）。この場合、較正の損は「全体の割合のずれの分」だけになる。標準偏差が S_MIN を超えていても S_MIN に近い形では、[1, logit(p)] の係数が不安定になりうるので、較正し直した対数損失の値の意味は弱い。どの形でも、標準偏差を値と一緒に公開する。
    - 案B：定義しない。標準偏差が S_MIN 未満の形では、較正し直した対数損失と較正の損を「定義しない」と書き、その形を含む上乗せの識別の目安も示さない。
    - 案C：小さい正のリッジ（例：1e-6、切片にも掛ける）を、すべての形に掛ける。行列は特異にならないが、確率がほぼ一定の形では、係数がリッジの大きさに強く依って大きくなり、値がリッジの選び方で動く。
    - どの案でも、標準偏差と、どの形にどの扱いを当てたかを公開する。
- 段2 はそのままの形なので、2−1・3−2・N3−2 の対数損失の差には、段2 の較正のずれが入る。2-d の識別の目安を並べて、どこまでが並べ方の違いかを示す。

### (4) 多重比較（Holm の方法）
- 族 S2（主張2）：2−1、N3−2、N4−N3、3−2、4−3 の5つの上乗せの対数損失の差（< 0 か）を一つの族にする。p の値と Holm の掛け方は 3章 (2) と同じ（族の大きさ 5、α = 0.025）。
- Holm で確かめた結果は、大きさと範囲の横に並べて示す。主張2 の結論を「勝った・負けた」の形では書かない。
- 判定の時点は 4章 (2) と同じ。
